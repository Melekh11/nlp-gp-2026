## Текущий статус реализации

Реализовано:

- Rasa Form со слотами для сбора данных интервью.
- Детерминированная валидация и извлечение слотов в custom actions.
- Объяснимый скоринг по всем пяти ролям.
- Ранжирование ролей вместо жесткого выбора одной роли.
- Risk flags и уточняющие вопросы.
- Итоговое сообщение для кандидата.
- Отчетный payload для рекрутера.
- Экспорт в CSV/JSON.
- Сценарии fallback, out-of-scope, repeat question, skip question и change answer.
- NLU-примеры для разговорного русского языка.
- Rasa synonyms и lookup tables для частых вариантов ролей, навыков, формата работы и доступности.
- Нормализация частых опечаток и разговорных форм.
- Smoke-test скрипт с многошаговыми сценариями.

Не реализовано:

- LLM-generated feedback.
- Web dashboard UI.
- Автоматическое исправление опечаток внешними библиотеками вроде `symspellpy`, `jamspell` или `pyspellchecker`.

## Основные измененные файлы

### `actions/actions.py`

Здесь находится основная бизнес-логика.

Ключевые зоны:

- Названия и описания ролей:
  - `ROLE_LABELS`
  - `ROLE_DETAILS`
- Нормализация алиасов ролей:
  - `ROLE_ALIASES`
  - `normalize_role()`
  - `infer_role()`
- Нормализация алиасов навыков:
  - `SKILL_ALIASES`
  - `extract_skills_from_text()`
- Нормализация опечаток:
  - `normalize_typos()`
  - `lower_text()`
- Парсинг зарплаты:
  - `parse_number()`
  - `parse_salary()`
- Парсинг опыта:
  - `parse_years()`
- Нормализация формата работы и доступности:
  - `normalize_work_format()`
  - `normalize_availability()`
- Скоринг кандидата:
  - `ROLE_SKILL_WEIGHTS`
  - `score_candidate()`
- Risk flags:
  - не хватает ключевых навыков
  - слишком мало опыта
  - высокие зарплатные ожидания
  - слабый или неизвестный английский
  - нет коммерческих проектов
- Отчет для рекрутера:
  - `build_recruiter_report()`
- Итог для кандидата:
  - `human_follow_up_questions()`
  - `final_message()`
- Экспорт:
  - JSON и CSV пишутся в папку `exports/`.

Важное поведение:

- Финальный ответ ориентирован на кандидата и не раскрывает внутренний скоринг.
- Финальный ответ использует секции:
  - `Спасибо, интервью завершено.`
  - `Итог`
  - `Почему`
  - `Уточняющие вопросы`
  - `Следующий шаг`
- Если не хватает важных данных, бот задает конкретные уточняющие вопросы, а не просто пишет, что что-то нужно уточнить.
- `normalize_role()` исправлен так, чтобы поддерживать канонические значения Rasa synonyms, например `data_analyst`.

### `scripts/dialog_smoke.py`

Smoke-test скрипт для многошаговой проверки через REST.

Он отправляет сценарии в Rasa REST webhook и пишет результат в:

```text
dialog_smoke_output.jsonl
```

Этот файл игнорируется Git.

Покрытые типы сценариев:

- MLOps-кандидат с медицинским ML-проектом.
- Data Analyst-кандидат с опечатками и неформальными формулировками.
- разговорный выбор роли.
- нелинейные ответы.
- поведение change-answer.

## Как запускать

Нужно два терминала из корня проекта.

Терминал 1:

```powershell
$env:TEMP='C:\rasa_tmp'
$env:TMP='C:\rasa_tmp'
$env:PYTHONIOENCODING='utf-8'
$env:SQLALCHEMY_SILENCE_UBER_WARNING='1'
.venv\Scripts\rasa.exe run actions
```

Терминал 2:

```powershell
$env:TEMP='C:\rasa_tmp'
$env:TMP='C:\rasa_tmp'
$env:PYTHONIOENCODING='utf-8'
$env:SQLALCHEMY_SILENCE_UBER_WARNING='1'
.venv\Scripts\rasa.exe shell
```

Action endpoint настроен в `endpoints.yml`:

```text
http://localhost:5055/webhook
```

Если custom actions падают с connection refused, значит action server не запущен.

## Валидация и обучение

Проверка синтаксиса:

```powershell
python -m py_compile actions\actions.py
```

Валидация Rasa data:

```powershell
$env:TEMP='C:\rasa_tmp'
$env:TMP='C:\rasa_tmp'
$env:PYTHONIOENCODING='utf-8'
$env:SQLALCHEMY_SILENCE_UBER_WARNING='1'
.venv\Scripts\rasa.exe data validate
```

Обучение:

```powershell
$env:TEMP='C:\rasa_tmp'
$env:TMP='C:\rasa_tmp'
$env:PYTHONIOENCODING='utf-8'
$env:SQLALCHEMY_SILENCE_UBER_WARNING='1'
.venv\Scripts\rasa.exe train --force
```

Известная проблема Windows:

- Запуск `.venv\Scripts\python.exe` или `.venv\Scripts\rasa.exe` может падать в sandbox-контексте, потому что путь проекта содержит кириллицу.
- В обычном пользовательском терминале запуск должен работать.
- Если Rasa падает с `PermissionError` на временных директориях, используйте `C:\rasa_tmp` через `TEMP` и `TMP`.

## UX-решения для кандидата

Кандидат не должен видеть:

- сырые scores
- внутренние названия slots
- детали реализации
- формулировки вроде "я бот"
- скрытую логику отбора

Кандидат может видеть:

- наиболее близкое направление
- альтернативные направления
- понятные причины
- конкретные уточняющие вопросы
- следующий шаг с рекрутером

Пример финальной структуры:

```text
Спасибо, интервью завершено.

Итог:
- По вашим ответам профиль ближе всего к направлению Data Analyst.
- Также можно рассмотреть: Data Scientist, Project Manager.

Почему:
- релевантные навыки: статистика и аналитика.
- вы рассматриваете это направление.
- есть аналитический опыт.

Уточняющие вопросы:
- Можете подробнее рассказать про опыт с SQL?

Следующий шаг: короткий созвон с рекрутером, чтобы уточнить опыт и ожидания.
```

## Рекомендации следующей команде

Для улучшения обработки опечаток лучше придерживаться такого порядка:

1. Добавлять точные NLU-примеры для частых пользовательских фраз.
2. Добавлять `synonym` для канонических значений.
3. Добавлять `lookup` для ролей, навыков, формата работы и доступности.
4. Добавлять детерминированную нормализацию в `actions/actions.py` только для высоконадежных случаев.
5. Не применять глобальный spellchecker ко всему сообщению, потому что он может испортить названия технологий, аббревиатуры, зарплатные значения и смешанный русско-английский текст.

Потенциальные следующие улучшения:

- Добавить автоматические NLU-тесты.
- Добавить больше smoke-сценариев и сравнение ожидаемого ranking ролей.
- Добавить легкий dashboard, который читает `exports/*.json`.
- Добавить recruiter-only report view.
- Добавить LLM-generated feedback отдельным optional action.
- Добавить внешний spellchecker только для отдельных полей, а не для полных сообщений.
